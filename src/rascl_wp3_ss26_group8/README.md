# rascl_wp3_ss26_group8

This ROS 2 package contains the Group 8 WP3 Task 1 and Task 2 application:

- calibrated three-axis arm forward and inverse kinematics;
- minimum-jerk joint trajectory generation;
- validated offline trajectory CSV input and output;
- `wp3_tsk1`, the single-target offline trajectory node;
- `wp3_tsk2`, the runtime `/goal_poses` pick-and-place node;
- Task launch files and regression tests.

Both nodes publish the joint order:

```text
[shoulder_joint, upperarm_joint, lowerarm_joint, spur_gear_joint]
```

to `/rascl_position_controller/commands`. Cartesian arm movement preserves the
current `spur_gear_joint`; explicit gripper steps move Drive 3 by exact relative
counts.

## Task 1 Node and Offline CSV

`wp3_tsk1` accepts one Cartesian TCP target in `base_link`. In planning mode it
reads `/joint_states`, applies optional board XY compensation, solves IK,
generates a 50 Hz minimum-jerk joint trajectory, and writes the trajectory CSV.

In offline input mode, set `input_csv` to an existing trajectory. The node then
checks:

- the exact CSV header and controller joint order;
- finite positions and strictly increasing timestamps;
- agreement between the first row and the current joint state;
- agreement between the final row and the requested Cartesian target.

It executes the timestamps and positions from the file without rerunning IK.
After motion, fresh joint feedback must satisfy both joint and TCP endpoint
tolerances.

The submitted task files are:

```text
trajectories/task1_input.csv   fixed four-stage assessed action list
trajectories/task1_output.csv  offline joint trajectory generated by group 9
```

The normal assessed command is top-level debug group `28`. Each Cartesian leg
generates `task1_output.csv` and executes that same offline file.

### Direct Fake-Hardware Example

Start fake hardware in one terminal:

```bash
ros2 launch rascl_description ros2_control.launch.py use_fake_hardware:=true
```

Plan in another terminal:

```bash
ros2 run rascl_wp3_ss26_group8 wp3_tsk1 --ros-args \
  -p target_x:=0.25 -p target_y:=0.00 -p target_z:=0.08 \
  -p duration:=4.0 -p rate_hz:=50.0 -p execute:=false \
  -p output_csv:=/root/ws/src/rascl_wp3_ss26_group8/trajectories/task1_output.csv
```

Execute the saved file:

```bash
ros2 run rascl_wp3_ss26_group8 wp3_tsk1 --ros-args \
  -p target_x:=0.25 -p target_y:=0.00 -p target_z:=0.08 \
  -p execute:=true -p save_csv:=false \
  -p input_csv:=/root/ws/src/rascl_wp3_ss26_group8/trajectories/task1_output.csv
```

The launch equivalent is `wp3_tsk1.launch.py`; it exposes both `input_csv` and
`output_csv`.

## Task 2 Node

`wp3_tsk2` is a long-running online node. It subscribes to:

```text
/goal_poses   geometry_msgs/msg/Point
```

`Point.x` and `Point.y` are the runtime cube-centre coordinates in metres.
`Point.z` is ignored because the validated pickup height is configured by the
node. Goals are queued and processed sequentially.

The fixed validated destination is `(0.1812, -0.0336) m`. Radius is used only
to select the existing inner, direct, or outer transfer action at thresholds
`0.17 m` and `0.20 m`. Actual Cartesian reachability is checked by IK at each
waypoint.

For each accepted cube the node:

1. approaches and descends to the published centre;
2. closes Drive 3 by `-150000` relative counts;
3. lifts and follows the selected transfer action;
4. reaches the fixed destination;
5. opens Drive 3 by `+150000` counts and retreats.

The inner and outer actions use their previously validated board-contact
waypoints to reduce cube tilt. Their coordinates and the fixed goal were not
changed when the online ROS interface was added.

Start through debug group `29`, or directly:

```bash
ros2 run rascl_wp3_ss26_group8 wp3_tsk2 --ros-args \
  -p execute:=true \
  -p require_torque_service:=true \
  -p output_directory:=/root/ws/src/rascl_wp3_ss26_group8/trajectories
```

Publish one runtime input:

```bash
ros2 topic pub --once /goal_poses geometry_msgs/msg/Point \
  '{x: 0.16, y: 0.08, z: 0.0}'
```

Task 2 writes one input CSV and one joint trajectory CSV per motion step, for
example:

```text
trajectories/task2_job_0001_input.csv
trajectories/task2_job_0001_step_01_approach_pick.csv
```

The launch equivalent is `wp3_tsk2.launch.py`.

## Coordinate and Calibration Convention

All targets use the URDF `base_link` frame in metres. `tcp_link` is fixed to
`lowerarm` at `[0.170, 0, 0.0179] m`: 170 mm along lowerarm +X with the drawing's
17.9 mm perpendicular offset. The physical `spur_gear_joint` CAD origin remains
at `[0.13916, 0, 0.0179] m`; gripper rotation therefore does not move the
planning TCP.

The joint-coordinate convention remains:

```text
URDF zero pose q = [0, 0, 0, 0]
automatic Home  = [0, +pi/2, +pi/2, 0]
```

The optional board XY affine correction changes only task coordinates before
IK. It does not change Homing, encoder offsets, or URDF geometry. The debug
script enables it for groups `9`, `10`, and `29`.

See [`docs/coordinate_convention.md`](docs/coordinate_convention.md) for the
full transformation and measured bounds.
